# Module B question — `tgt_ceacam5`

Paired with the Module E run for the same target (see `../../module_e_normal_tissue_risk/question/tgt_ceacam5.md` for why `CEACAM5` was picked).

> **在 `mcrc_preop_chemotherapy_crlm` 这个 indication（preoperative chemo/RT 后的 matched primary/CRLM 标本）里，CEACAM5 是否有足够多能被地址访问的恶性上皮细胞？**

`indication_id = mcrc_preop_chemotherapy_crlm` — chosen because it is the territory `GSE225857` and `GSE178318` (this module's two `CORE_ACTIVE`/`every_target` datasets per `DATA/registry/module_classification.tsv`) sample, not a broader indication their data can't speak to. Its `prior_therapy` field was loosened 2026-08-23 (PR #73 round 1 review) from a specific regimen (`CAPEOX_OR_FOLFOX_BEV`) to `PREOPERATIVE_CHEMOTHERAPY_AND_OR_RT`, matching what `GSE225857`'s own metadata actually supports — `GSE178318` is itself a mixed cohort where only 3 of 6 patients received a matching regimen (per `DATA/registry/GSE178318/sample_map.tsv`) and the other 3 are treatment-naive, so neither dataset is uniformly "this indication."

## Status: `GSE178318` has an epithelial-proxy answer and a materially sharper (but still not DNA-level) real InferCNV signal (2026-08-26) — the malignant-cell question is materially advanced, not fully closed

See `data_lock/tgt_ceacam5.md` and `analysis_contracts/tgt_ceacam5.md` for the real, QC-filtered result: every one of `GSE178318`'s 6 patients (3 treated -- `TE004`, `indication_id=mcrc_preop_chemotherapy_crlm`; 3 treatment-naive -- `TE005`, `indication_id=mcrc_liver_metastasis`, kept as separate context evidence) has a detectable CEACAM5-positive epithelial-proxy subpopulation in both primary and liver-metastasis tissue. **This is EPCAM-based epithelial-proxy screening, not malignancy-confirmed** -- the source publication itself confirms malignancy via InferCNV, which is not reproduced here. A chromosome-arm-level CNV score was then attempted (`analysis_contracts/infercnv_lite_gse178318.md`, `TE006`), scored on the same treated-cohort (COL15/COL17/COL18) epithelial-proxy cells and reference as TE004, to try to close that gap directly; it found a modest CNV-score shift (2.02% clearing the held-out reference's own threshold vs. 1.00% for the reference itself, a 2.02x enrichment), directionally consistent with malignancy, but ambiguous and nonconfirmatory at the single-cell level -- not attributable with this coarse method to CNV signal vs. lineage-driven expression differences vs. resolution loss, treated as co-equal, un-excluded explanations -- an honest inconclusive result, not a negative-for-malignancy one. **2026-08-26 (Next-handoff item 1, revised in round 1 review of PR #89)**: a real gene-window InferCNV run (`analysis_contracts/infercnv_gse178318.md`, `TE043`), using `infercnvpy` (a maintained, `inferCNV`-inspired Python implementation, explicitly experimental per its own documentation) on the exact same populations as `TE006` (verified by direct cell-set comparison, not just matching counts), found a materially sharper 21.89x descriptive tail-enrichment ratio (versus `TE006`'s 2.02x; a real mitochondrial-chromosome bug was found and fixed before this final number), with `CEACAM5`-positive fraction higher in `CNV_HIGH` than `CNV_LOW` cells in every one of the 6 sample strata. Two added sanity checks support this: a block-coherence check (`CNV_HIGH`'s signal concentrates on `chr20`/`chr7`, independently confirmed recurrent CRC copy-number-gain hotspots, far more than the near-uniform reference) and a leave-`CEACAM5`-out control (negligible effect on which cells are called `CNV_HIGH`, ruling out target leakage). This is real progress -- but still expression-based CNV inference from an explicitly experimental package, not a DNA-level malignancy call (see that file's "Explicit limitations"). So the question this file poses (\"...能被地址访问的恶性上皮细胞\") is materially better-answered than before but still not conclusively closed. `GSE225857` -- this module's other `CORE_ACTIVE` dataset for this indication -- was blocked on CNSA access when this question was first posed; it has since produced its own real result via GEO's public route (`TE027`, 2026-08-24, PR #81), a second, independent, author-defined-tumor-cell screen for the same target and indication. That screen is likewise not CNV-confirmed malignancy (see `data_lock/tgt_ceacam5.md`'s `GSE225857` section), so the question this file poses still has no fully DNA-level-confirmed answer from either dataset -- this mirrors the discipline this repository has used for every genuine gap since the Phase 1 verification pass (PR #71): preserve the gap, don't force a closure, and don't let a proxy result (even a materially stronger one) stand in for the malignancy-confirmed claim the question actually asks for.
