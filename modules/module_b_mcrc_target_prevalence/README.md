# Module B — MCRC_TARGET_PREVALENCE

## Goal

> **mCRC 里到底有没有足够多能被 X 地址访问的癌细胞？**

## Inputs

- `GSE225857` — 6 CRLM patients, 27 matched primary/LM/adjacent/PB samples, all preoperative chemo and/or RT, scRNA + spatial.
- `GSE178318` — matched primary + CRLM scRNA, 6 patients, 3 with preoperative chemo.
- Refractory/clinical bulk datasets registered under this module in `../../DATA/registry/module_classification.tsv`.

## Per-target output

For each candidate X from Module A:

- malignant-cell detection
- X-high fraction
- patient-positive fraction
- between-patient heterogeneity
- within-patient heterogeneity
- metastatic lesion coverage

## Naming rule

Bucket output as `RNA_no / RNA_low / RNA_high`. This can **never** be upgraded to `surface-density high` — not even by a completed Module D protein calibration. Module D only provides protein-level support/concordance (whole-tissue MS ≠ malignant-cell membrane density, PDO protein ≠ tumor surface density); a real surface-density claim requires a target-specific quantitative surface assay or equivalent direct evidence, which is neither `RNA_high` nor a Module D result. Record `evidence_directness` accordingly in `../../schemas/target_evidence.tsv` (`UNCALIBRATED_PROXY` for RNA alone, `CALIBRATED_PROXY` at best once Module D protein concordance exists, never `DIRECT` from this module).

## Cannot prove

scRNA ≠ surface density. Small cohorts (n=6) are within-cohort descriptive statistics, not population prevalence claims until replicated.

Output rows `target_id`-keyed per `../../schemas/target_evidence.tsv`.

**CNV-based malignancy confirmation attempted, 2026-08-23 — ambiguous, not confirmatory.** New `../../scripts/infercnv_lite_gse178318.py` builds a chromosome-arm-level CNV score (gene-to-arm mapping from the local HGNC gene-position reference, `config/external_sources.yaml`'s `module_b_gene_position_reference` block, path resolved from that YAML and checksum-locked via `DATA/reference/hgnc_gene_id_mapping_source_lock.tsv`; 25,376 of 33,694 genes resolve to an arm, 43 arms with >=10 genes) scored against a held-out half of a tumor-site immune reference — a coarser, independently-designed approximation of the source paper's own fine-grained InferCNV, not a reproduction. Both the reference and the epithelial-proxy population are restricted to the 3 treated patients (`COL15`/`COL17`/`COL18`), matching `TE004`'s `indication_id=mcrc_preop_chemotherapy_crlm` (a pooled six-patient version — 82% treatment-naive cells — is kept only as a method diagnostic, never as the canonical statistic; an earlier round of this PR wrongly reported the pooled numbers under this treated-cohort row). Result: epithelial-proxy cells (n=1,786) show a modest median CNV-score shift vs. the held-out treated-cohort reference (n=19,002; 1.32 vs 0.63, ~2.1x), directionally consistent with malignant signal, but the distributions overlap substantially — 36/1,786 (2.02%) of epithelial-proxy cells clear the held-out reference's own 99th-percentile threshold vs. 190/19,002 (1.00%) of the held-out reference's own cells (enrichment ratio 2.02x, a modest enrichment), and per-sample counts above that threshold are mostly single-digit (0-22 cells across the 6 treated samples), too small for a reliable prevalence estimate. This coarse arm-level method is missing within-cell gene-order smoothing and a centering/reference-subtraction step relative to real InferCNV workflows (not primarily "no cross-cell smoothing"), and its aggregate score erases gain/loss direction; lineage-driven expression differences (epithelial vs immune, unrelated to copy number) are an equally plausible, co-equal explanation for the shift, not a secondary caveat — so the result is best read as an observed CNV-like score shift with an ambiguous, nonconfirmatory signal, not evidence the cells aren't malignant. One `target_evidence.tsv` row (`TE006`, `evidence_level=EXPLORATORY_UNDERPOWERED`), backed by `EV014`. **Does not supersede `TE004`/`TE005`** — those remain Module B's primary evidence for this target; Module B's actual malignant-cell prevalence question for `tgt_ceacam5` still has no confirmatory answer. **Real gene-window InferCNV run, 2026-08-26 (Next-handoff item 1, revised in round 1 and round 2 review of PR #89) — materially sharper, still not DNA-level.** New `../../scripts/infercnv_gse178318.py` uses `infercnvpy` (a maintained, `inferCNV`-inspired Python implementation — pip-installable and network-reachable in this environment; its own documentation states it is still experimental and not formally validated against Broad `inferCNV`, only "similar, but not identical" — corrected framing after round 1 review found an earlier version overstated it as "peer-established"/"field-standard") to address the two gaps the CNV-lite attempt's own limitations section named: real gene-order window smoothing (via a new `DATA/reference/ensembl_gene_positions_grch38_release110.tsv` base-pair position table, 97.4% gene coverage — `../../scripts/build_ensembl_gene_positions.py`) and an explicit reference-centering step (`infercnvpy`'s own `reference=` parameter, fit from the fit-half of the same reference population). Population definitions are reused byte-for-byte from `infercnv_lite_gse178318.py`'s own `build_populations()` — confirmed to reproduce the exact same population **cell sets** (not just sizes; round 1 review required an actual set-equality check, not just matching counts) — so the only thing that changed is the CNV-inference algorithm itself. Round 1 review also caught and required fixing a real bug: mitochondrial genes were mapped to `"chrMT"`, which `infercnvpy`'s own windowing code (which only recognizes the literal string `"chrM"`) does not exclude, silently contaminating the CNV score with mitochondrial RNA signal — fixed, and the entire analysis re-run. Corrected result: a **21.89x descriptive tail-enrichment ratio** of `CNV_HIGH` cells among the epithelial-proxy population versus the held-out reference's own null rate (versus the arm-level attempt's 2.02x; the pre-fix number was a close-but-confirmed-different 22.79x) — and `CEACAM5`-positive fraction is higher in `CNV_HIGH` than `CNV_LOW` cells in **every one of the 6 sample strata**. Two sanity checks were added (at the reviewer's request): a leave-`CEACAM5`-out control cleanly rules out material `CEACAM5`-expression leakage as a driver of `CNV_HIGH` membership (excluding `CEACAM5` from the CNV-inference input changes the `CNV_HIGH` cell set by <1%, Jaccard=0.992) — this answers "did `CEACAM5` create its own association" (no), not "does `CNV_HIGH` actually represent malignant cells" (a separate question the CNV method itself, not this control, has to answer). The block-coherence check, corrected in round 2 review from a magnitude-only metric to an actual spatial-contiguity-and-sign test, gives a genuinely mixed, honestly-disclosed result: `CNV_HIGH`'s `chr7`/`chr20` signal (independently confirmed recurrent CRC copy-number-gain hotspots) is real, spatially contiguous, and consistently gain-like — but the identical broad pattern also appears, at smaller magnitude, in `CNV_LOW` and even reference cells (for `chr20`, the exact same window range in all three groups), so this is a graded-magnitude finding on a shared spatial pattern, not a pattern exclusive to `CNV_HIGH`. Still expression-based CNV inference from an explicitly experimental package, not a DNA-level call — see `analysis_contracts/infercnv_gse178318.md`'s full "Explicit limitations" and "Results" sections. One new `target_evidence.tsv` row (`TE043`, `evidence_level=SCREENING_LEVEL`, `confidence=LOW` — revised down from an earlier round's `MEDIUM` in round 3 review of PR #89: `CNV_HIGH`/`CNV_LOW` are themselves defined by splitting on CNV magnitude, so a magnitude gradient across those same groups is not independent confirmation of anything beyond the split's own definition, and the earlier "a purely-random process would not reproduce this" framing is unsupported once a known, already-acknowledged non-random alternative — a systematic lineage/reference-choice effect — could produce the same pattern), backed by `EV051` — does not supersede `TE004`/`TE006`, which remain in the record as their own honestly-characterized attempts; Module B's malignant-cell prevalence question for `tgt_ceacam5` is materially advanced but not fully closed by this result.
