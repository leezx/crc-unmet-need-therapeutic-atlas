## `GSE178318` — matrix, gene index, patient/sample annotation, QC, and epithelial-proxy split are all present; malignancy is NOT confirmed

- `DATA/registry/GSE178318/source_manifest.tsv` and `file_inventory.tsv` record `GSE178318_barcodes.tsv.gz`, `GSE178318_genes.tsv.gz`, and `GSE178318_matrix.mtx.gz` (520.7 MB, 33,694 genes x 140,281 cells, SHA256-verified) as downloaded 2026-08-11. All three files are physically present (gitignored, never deleted) at `archive/phase2_fetal_state_track_v1/phase2/03_data/raw/GSE178318/`. `source_manifest.tsv`'s DOI was corrected 2026-08-23 (round 1 review): the previously-recorded `10.1038/s41598-021-96568-3` does not resolve; the real paper is `10.1038/s41421-021-00312-y` (Cell Discovery 2021).
- `CEACAM5` (`ENSG00000105388`) confirmed present in the gene index (row 31446).
- `DATA/registry/GSE178318/sample_map.tsv` carries real patient/sample-level annotation for all 15 barcode groups, including which 3 of 6 patients (`COL15`/`COL17`/`COL18`) actually received preoperative chemotherapy.
- **QC**: `scripts/annotate_gse178318_cell_types.py` applies a paper-aligned operationalization of the source publication's own criteria (>=500 detected genes and <=15% mitochondrial UMI, both stated explicitly in the paper; per-sample 3-SD outlier removal on log-total-UMI, per the paper's own stated rule; the same 3-SD rule extended to gene-count outliers, which the paper describes only as "unusually high or low," not as an explicit 3-SD step) — 123,330 of 140,281 barcodes pass (paper: 111,292 of 140,281 via its own pipeline; not expected to match exactly, batch definition differs).
- **Epithelial-proxy identification**: EPCAM expression alone (matching the paper's own stated method), scored as a marker-average fraction of total UMI to avoid the earlier version's bug where categories with more marker genes were structurally favored.
- **What is still not done, and is not attempted in this pass**: the source publication confirms EPCs are malignant via InferCNV (transcriptome-inferred copy-number variation). That step needs a genomic gene-position reference and a chosen normal-cell reference population — real additional engineering, not reproduced here. This screen stops at "EPCAM-high, QC-passing cell in a tumor-site specimen," stated as an epithelial-proxy, not a malignancy-confirmed result, everywhere it is used.

## What would close Module B's actual malignant-cell prevalence question for this target

**Attempted 2026-08-23** via `scripts/infercnv_lite_gse178318.py` — a chromosome-arm-level CNV score (gene-position reference from `DATA/1.Databases/HGNC_gene_id_mapping`, resolved via `config/external_sources.yaml`'s `module_b_gene_position_reference` `path_env_var` and checksum-locked via `DATA/reference/hgnc_gene_id_mapping_source_lock.tsv`) against a held-out half of a tumor-site-immune reference population, both restricted to the 3 treated patients (`COL15`/`COL17`/`COL18`) matching `TE004`'s treated-cohort `indication_id`. **Result: ambiguous, not confirmatory** — see `analysis_contracts/infercnv_lite_gse178318.md` for the full method and honest results. Epithelial-proxy cells (n=1,786) show a modest median CNV-score shift over the held-out treated-cohort reference (n=19,002; 1.32 vs 0.63, directionally consistent with malignancy) but the two distributions overlap substantially, and only 36/1,786 (2.02%) of cells individually clear the held-out reference's own 99th-percentile threshold, vs. 1.00% for the reference's own cells at that same threshold (enrichment ratio 2.02x) — too few per sample for a reliable confirmed-malignant CEACAM5 prevalence number. This coarse arm-level method is missing within-cell gene-order smoothing and a centering/reference-subtraction step relative to real InferCNV workflows (not primarily "no cross-cell smoothing"), and lineage-driven expression differences (epithelial vs immune, unrelated to copy number) are an equally plausible, co-equal alternative explanation for the shift — neither is evidence that the epithelial-proxy population isn't malignant. **Still open**: a finer-grained, gene-window InferCNV reproduction (or a real InferCNV package run, if one becomes available in this environment) could have more power than this arm-level attempt. For `GSE225857`: CNSA access-terms review is done (2026-08-24, confirmed `CONTROLLED_ACCESS`) — but the cheaper, not-yet-done next step is checking whether GEO's own public per-GSM metadata (`GSM7058754`/`GSM7058755`) resolves to patient/site/treatment level before considering a DAC application to the data submitter.
