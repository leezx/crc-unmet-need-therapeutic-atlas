## What would close Module B's actual malignant-cell prevalence question for this target

**Attempted 2026-08-23** via `scripts/infercnv_lite_gse178318.py` — a chromosome-arm-level CNV score (gene-position reference from `DATA/1.Databases/HGNC_gene_id_mapping`, resolved via `config/external_sources.yaml`'s `module_b_gene_position_reference` `path_env_var` and checksum-locked via `DATA/reference/hgnc_gene_id_mapping_source_lock.tsv`) against a held-out half of a tumor-site-immune reference population, both restricted to the 3 treated patients (`COL15`/`COL17`/`COL18`) matching `TE004`'s treated-cohort `indication_id`. **Result: ambiguous, not confirmatory** — see `analysis_contracts/infercnv_lite_gse178318.md` for the full method and honest results. Epithelial-proxy cells (n=1,786) show a modest median CNV-score shift over the held-out treated-cohort reference (n=19,002; 1.32 vs 0.63, directionally consistent with malignancy) but the two distributions overlap substantially, and only 36/1,786 (2.02%) of cells individually clear the held-out reference's own 99th-percentile threshold, vs. 1.00% for the reference's own cells at that same threshold (enrichment ratio 2.02x) — too few per sample for a reliable confirmed-malignant CEACAM5 prevalence number. This coarse arm-level method is missing within-cell gene-order smoothing and a centering/reference-subtraction step relative to real InferCNV workflows (not primarily "no cross-cell smoothing"), and lineage-driven expression differences (epithelial vs immune, unrelated to copy number) are an equally plausible, co-equal alternative explanation for the shift — neither is evidence that the epithelial-proxy population isn't malignant. **Still open**: a finer-grained, gene-window InferCNV reproduction (or a real InferCNV package run, if one becomes available in this environment) could have more power than this arm-level attempt. For `GSE225857`: the non-immune tumor-cell screen above (2026-08-24, PR #81) is a real second-cohort result, but is built on the source publication's own cluster call, not an independent CNV re-derivation here either — the same "still open" caveat applies to both datasets.
