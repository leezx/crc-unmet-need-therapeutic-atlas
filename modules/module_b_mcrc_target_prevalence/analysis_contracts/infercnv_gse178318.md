# Module B — real gene-window InferCNV for `GSE178318`'s epithelial-proxy cells

**Status: LOCKED. Materially different result from the arm-level CNV-lite attempt — real, but still expression-based, not DNA-level.**

Written for Next-handoff item 1: `infercnv_lite_gse178318.md`'s own "Explicit limitations" section named the coarse arm-level method's two biggest gaps relative to a real InferCNV-style workflow — no gene-order local structure (a moving window along genes in true genomic order) and no explicit centering/reference-subtraction step. This file's method addresses both directly, using `infercnvpy` (a real, actively-maintained scanpy-ecosystem reimplementation of the Broad Institute's `inferCNV` algorithm) — confirmed pip-installable and network-reachable in this environment 2026-08-26, the "actual InferCNV package if one becomes available" path the PR #75/#76 reviewer explicitly named as acceptable alongside a from-scratch gene-window reimplementation.

## What this is and is not

This is expression-based CNV *inference* — a moving-window average of reference-centered log expression across genes in genomic order — not a DNA-level (WGS/WES/array) copy-number call. `infercnvpy`'s algorithm and its use here follow the field-standard approach (the same general strategy `GSE178318`'s own source publication used, per its own Methods), but this is an independent run against this repository's own reference-population choice, not a reproduction of the paper's own exact numbers, thresholds, or reference set (not disclosed in the Methods excerpt available to this analysis). `evidence_directness` stays `UNCALIBRATED_PROXY` — an expression-based CNV score is still an indirect readout of malignancy, not malignancy itself, and not a surface/membrane density claim.

## Method (locked before running results were known — population definitions, split seed, and package defaults chosen first)

1. **Population definitions reused byte-for-byte from `infercnv_lite_gse178318.py`'s own `build_populations()`** (imported directly, not reimplemented): reference = QC-passing, `immune`-classified, tumor-site (`PRIMARY_CRC`/`LIVER_METASTASIS`, never `PBMC`), treated-cohort-only (`COL15`/`COL17`/`COL18`) cells; epithelial-proxy = the same restriction with `epithelial`-classified cells. QC thresholds, `classify_cell()`, and all constants (`MIN_DETECTED_GENES`, `MAX_MITO_FRACTION`, `BATCH_OUTLIER_SD`) are imported directly from `annotate_gse178318_cell_types.py`, not reimplemented. This is deliberate: the only thing this file's method changes relative to the CNV-lite attempt is the CNV-inference algorithm itself — confirmed empirically (see Results) to reproduce the exact same population sizes (38,003 reference / 1,786 epithelial-proxy cells) as the CNV-lite run, so any difference in the two methods' results is attributable to the algorithm, not a silently different cell-selection pipeline.
2. **QC/classification statistics computed by vectorized sparse-matrix reductions**, not `annotate_gse178318_cell_types.py`'s own streaming per-line loop — mathematically identical (same definitions, same constants, same `classify_cell()` call), verified empirically by reproducing that script's exact population counts. This repository's own `scripts/test_infercnv_gse178318.py` unit-tests the vectorized reduction functions against a small synthetic fixture matrix with hand-computed expected values.
3. **Reference/epithelial-proxy fit-holdout split**: same seed (`--seed 42`, matching `infercnv_lite_gse178318.py`'s own default) and same 50/50 `random.shuffle` split of the reference population into fit/holdout halves, for direct methodological comparability with the arm-level attempt.
4. **Gene genomic positions**: `DATA/reference/ensembl_gene_positions_grch38_release110.tsv` (built by `scripts/build_ensembl_gene_positions.py` from Ensembl's own public GTF, release 110 — chosen as a recent, stable GRCh38 release; not necessarily the exact release `GSE178318`'s own CellRanger reference used, which is not recorded in the dataset's own metadata, but gene body coordinates are highly stable across nearby GRCh38 Ensembl releases for the large majority of genes). 32,807/33,694 (97.4%) of `GSE178318`'s own genes resolve to a position — materially higher than the arm-level method's 75.3% arm coverage, because base-pair position data changes far less across Ensembl releases than not-yet-assigned/reserved HGNC cytogenetic-band entries do. The 2.6% that don't resolve are excluded from the CNV-window computation, not guessed at.
5. **Preprocessing**: standard `scanpy` library-size normalization (`sc.pp.normalize_total(target_sum=1e4)`) + `sc.pp.log1p()` on raw UMI counts before CNV inference — the standard `infercnvpy`/`inferCNV` precondition (raw counts across cells of different sequencing depth are not directly comparable).
6. **Reference vector**: mean of the normalized/log1p expression across the **fit half of the reference population only** (never the held-out half, never epithelial-proxy cells), passed directly to `infercnvpy` via its `reference=` parameter — not re-estimated internally from cells this analysis needs to score against it.
7. **`infercnvpy.tl.infercnv()` called with the package's own defaults, not tuned**: `window_size=100` genes, `step=10`, `lfc_clip=3`, `dynamic_threshold=1.5`, `exclude_chromosomes=('chrX','chrY')`. Using the package's own established defaults, rather than searching for parameters that produce a particular desired result, is the deliberate, defensible choice here — a real limitation is that these defaults are not validated specifically against this dataset (see Limitations).
8. **Per-cell CNV score**: `mean(|X_cnv[cell, :]|)` across all smoothed genomic windows for that cell — directly analogous to `infercnvpy`'s own `cnv.tl.cnv_score()` aggregate (mean of absolute CNV values), applied per-cell instead of per-Leiden-cluster (no clustering step introduced here, which would need its own locked hyperparameters this repository has no basis to choose).
9. **`CNV_HIGH`/`CNV_LOW` threshold**: the held-out reference half's own 99th percentile of this per-cell score — same percentile and same "held-out half's own null distribution" methodology as the arm-level attempt, for direct comparability.
10. **Output**: CEACAM5-positive fraction recomputed within `CNV_HIGH` epithelial-proxy cells, per sample, for the 3 treated patients — same output table shape as `infercnv_lite_gse178318.py`'s own results table, for a direct side-by-side comparison.

## Explicit limitations (locked before running)

- **Expression-based, not DNA-level** — even with real gene-window smoothing, this is still an inferred, indirect CNV proxy, not a WGS/WES/array copy-number call. A cell scoring `CNV_HIGH` here is malignancy-*consistent*, not malignancy-*confirmed* at the DNA level.
- **Reference genome release mismatch (undisclosed)**: `GSE178318`'s own CellRanger reference release is not stated in its available metadata; this analysis uses Ensembl release 110 gene positions, cross-checked only by an empirical 97.4% ID-resolution rate against the dataset's own gene index, not by confirming an exact release match.
- **Package defaults, not dataset-tuned or independently validated here**: `window_size`/`step`/`lfc_clip`/`dynamic_threshold` are `infercnvpy`'s own published defaults. This avoids the appearance of parameter search for a desired result, but this analysis does not independently establish that these defaults are optimal for `GSE178318`'s specific sequencing depth/gene panel.
- **No spatial/heatmap confirmation of a genuine block-structured CNV pattern.** A real aneuploid cell should show coordinated gains/losses concentrated at specific chromosomal segments, consistently across cells — the strongest visual/statistical confirmation typical InferCNV workflows use. This analysis's single aggregate-score threshold does not check for that spatial consistency; it is possible for a cell to score `CNV_HIGH` on this aggregate without a biologically coherent CNV pattern (e.g., diffuse noise inflating the mean absolute value). `calculate_gene_values=False` (not requested here) — per-gene/per-segment CNV values, including specifically at `CEACAM5`'s own chr19 locus, are not available from this run; a natural, not-yet-pursued follow-up.
- **Lineage confounding is reduced, but not eliminated, relative to the arm-level attempt.** Real gene-window smoothing with reference-centering is specifically designed to distinguish a genuinely coordinated shift across many genes in a contiguous genomic region (the CNV-specific signature) from a smooth, broad, lineage-driven expression difference (epithelial vs. immune transcriptional programs) that would not produce that same spatially-coherent pattern — this is the core reason InferCNV-style tools are trusted for this purpose in the field, and a real methodological reason to expect this result is less confounded by lineage than the arm-level attempt's single coarse per-arm bucket could be. It is not proof that lineage confounding is fully excluded, since this analysis does not independently verify the spatial-coherence property (previous limitation) that would make that case airtight.
- **Not a reproduction of `GSE178318`'s own published InferCNV result** — an independent run with this repository's own reference-population choice (tumor-site immune cells, not necessarily the source publication's own reference set, which is not disclosed in the Methods excerpt available to this analysis).

## Results (2026-08-26)

Run via `python3 scripts/infercnv_gse178318.py --gene CEACAM5`. Full table: `results/tgt_ceacam5_infercnv_attempt.tsv` (gitignored, not committed — regenerable). Runtime: ~85 seconds on this environment (17 GB RAM / 8 CPU); memory peak well within budget (a ~40,000-cell x 32,807-gene subset AnnData, not the full 140,281-cell matrix, since only the reference fit/holdout halves and epithelial-proxy cells are needed).

- **Population sizes, confirmed identical to the CNV-lite attempt**: reference n=38,003 (fit n=19,001, holdout n=19,002); epithelial-proxy n=1,786.
- **Fit-half reference CNV score median: 0.00659.**
- **Held-out reference CNV score (n=19,002; the threshold is this half's own 99th percentile, so its own exceedance rate is the ~1% null rate by construction, not independent evidence)**: median=0.00661, p90=0.00875, p99=0.01137 (**threshold=0.01137**).
- **Epithelial-proxy CNV score (n=1,786)**: min=0.00150, p10=0.00526, p25=0.00644, **median=0.00828**, p75=0.01102, p90=0.01350, p99=0.01802, max=0.05437.
- **`CNV_HIGH` (score > threshold): epithelial-proxy 407/1,786 (22.79%) vs. held-out reference's own 190/19,002 (1.00%) — enrichment ratio 22.79x.**

**The finding, stated at the confidence level this method actually supports**: this real gene-window InferCNV run shows a **materially sharper separation** between the epithelial-proxy population and the held-out reference than the arm-level attempt did — 22.79x enrichment above threshold, versus the arm-level method's 2.02x, and 4 of 6 sample strata now have double-digit-or-larger `CNV_HIGH` counts (5-214 cells, versus the arm-level attempt's mostly-single-digit 0-22), enough for a real per-sample `CEACAM5`-positive-fraction estimate in those strata (`COL17` remains small in both methods — a real limitation of that sample's own epithelial-proxy yield, not of the CNV method). In **every one of the 6 sample strata**, the `CEACAM5`-positive fraction is higher in `CNV_HIGH` cells than in `CNV_LOW` cells (a consistent, not cherry-picked, direction) — real evidence that `CEACAM5` positivity is enriched in the subset of epithelial-proxy cells this method's CNV signal is most consistent with malignancy, on top of (not instead of) the plain epithelial-proxy positivity `TE004` already reports.

This is a real, materially different result from the arm-level attempt's own "ambiguous, nonconfirmatory" conclusion — but per the Limitations above, it is still an expression-based CNV score, not a DNA-level malignancy confirmation, run with package-default parameters not independently validated against this specific dataset, and without the spatial/heatmap check that would make the case for "this specific `CNV_HIGH` cell truly carries a coherent copy-number-altered genome" airtight rather than "this cell's aggregate CNV-window signal clears an empirically-set threshold." Module B's malignant-cell prevalence question for `tgt_ceacam5` is materially advanced by this result but not fully closed by it.
