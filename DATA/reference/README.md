# DATA/reference/

Small, versioned lookup tables that join against external sources declared in `config/external_sources.yaml`. These are checked in because they encode a one-time verification pass (or a checksum lock), not something a script should silently re-derive or fabricate at run time.

- `adcdb_asset_antigen_crossref.tsv` — for each ADC candidate row in `ADCDB_CLAUDE_REDO_PATH/DATA/feasibility/adc_candidates.tsv` with `status=VALIDATED` and a recognized clinical stage, the antigen (surface target) it was manually cross-referenced against in `ADCDB_PUBLISHED_PATH/ADCs/*.md`'s `antigen:` wikilink field, a machine-checked `resolution_status` (`RESOLVED_DIRECT` — 27 rows, a dedicated `ADCs/<asset>.md` file's own `antigen:` field; `RESOLVED_BACKLINK` — 2 rows, `sigvotatug vedotin`/`bulumtatug fuvedotin`, resolved via the antigen file's own "Related ADCs" backlink instead of a dedicated ADC file; `UNRESOLVED_SOURCE_GAP` — 1 row, `glembatumumab vedotin`, whose ADC detail file is referenced from `ADC.index.md` but missing from the local vault), and a free-text `resolution_note` explaining how. `scripts/build_target_seed_universe.py` reconciles this file's `asset_entity_id` set against `adc_candidates.tsv`'s expected set on every run and hard-fails on drift (missing row, stale row, duplicate, or a `RESOLVED_*` row whose antigen file has vanished) — a partial/stale seed universe must never be emitted silently. Built 2026-08-23; re-verify and regenerate this file, not just append to it, if `adc_candidates.tsv` gains rows.
- `uniprot_accession_map.tsv` — UniProt accession per gene symbol, retrieved from the UniProt REST API (`source_query_url`) on 2026-08-23 and cross-checked against each antigen file's own `Uniprot Entry` mnemonic (e.g. `ERBB2_HUMAN`) in `ADCDB_PUBLISHED_PATH/Antigens/*.md` — all 23 matched exactly. `ADCDB_PUBLISHED_PATH`'s own antigen pages carry an HGNC ID and gene symbol but not a UniProt accession number, hence this separate lookup.
- `hgnc_gene_id_mapping_source_lock.tsv` — a checksum lock (SHA256, file size, access date), not a lookup table: pins the exact snapshot of the externally-reused `HGNC_GENE_ID_MAPPING_PATH/raw/hgnc_custom_download.tsv` (Module B's gene→chromosome-arm reference, `config/external_sources.yaml`'s `module_b_gene_position_reference`) that `scripts/infercnv_lite_gse178318.py` was run against. Verified at runtime, hard-fail on mismatch — the same reasoning as `DATA/registry/GSE178318/source_manifest.tsv`'s checksums, applied to an external, non-registry source.
- `ensembl_gene_positions_grch38_release110.tsv` — real genomic positions (chromosome, base-pair start/end) for 62,700 genes on standard contigs (1-22/X/Y/MT), parsed 2026-08-26 from Ensembl's own public GTF (`Homo_sapiens.GRCh38.110.gtf.gz`, release 110, sha256 recorded in `scripts/build_ensembl_gene_positions.py`'s own docstring — the 54 MB source GTF itself is not retained in this repository, only this derived table). Built for `scripts/infercnv_gse178318.py`'s real gene-window InferCNV (via `infercnvpy`), which needs base-pair positions to sort genes into genomic order for its moving-window smoothing — a materially finer requirement than the arm-level `hgnc_gene_id_mapping_source_lock.tsv` above can meet (that source has no base-pair coordinates). Coverage against `GSE178318`'s own gene index: 97.4% (32,807/33,694).

The first two files are inputs to Module A's `ADC_TARGET_SEED_UNIVERSE.tsv` build — see `scripts/build_target_seed_universe.py` and `DATA/registry/ADC_TARGET_SEED_UNIVERSE.tsv`. `hgnc_gene_id_mapping_source_lock.tsv` and `ensembl_gene_positions_grch38_release110.tsv` are Module B's, for the arm-level and gene-window CNV scripts respectively.
