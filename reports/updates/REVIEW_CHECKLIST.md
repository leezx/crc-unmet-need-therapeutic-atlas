# Pinned-target update review checklist

This checklist applies when `reports/updates/github_tree_update_candidates.tsv` reports `update_available=TRUE`.

1. Confirm the report was generated by the scheduled or manually dispatched workflow and inspect the target row.
2. Verify that `repository`, `tracking_ref`, and `pinned_commit` match `config/github_tree_targets.tsv`.
3. Resolve the proposed latest SHA through GitHub ref metadata and record the exact 40-character commit SHA in the review notes.
4. Review the fixed-commit tree metadata for the configured prefix; compare paths, Git blob SHAs, sizes, counts, and byte totals with the prior inventory.
5. Identify additions, removals, renames, size changes, and classification changes. Keep biological content out of this repository.
6. Update the pinned commit and inventories only in a separate, human-reviewed PR. Do not let the weekly workflow rewrite pins automatically.
7. Require CI and an external review before merge. If the provenance boundary is unclear, leave the target pinned and mark the review blocked.

The update checker is metadata-only: it does not read blobs, download files, clone repositories, execute upstream code, or infer that a changed tree is biologically validated.
