Source: `Asset-Generation-OS-architecture.md` → `CRC-Atlas工业化重构`（用户手工备注）, 2026-08-21. This is a **scope pivot**, not a data loss: the repository's single task is now

## Module A seed universe build (2026-08-23)

`DATA/registry/ADC_TARGET_SEED_UNIVERSE.tsv` was generated by the new `scripts/build_target_seed_universe.py`, which resolves both Module A source locations from `config/external_sources.yaml` via their `path_env_var` (fails closed if unset — never falls back to `example_local_path`) and joins:

- `$ADCDB_CLAUDE_REDO_PATH/DATA/feasibility/adc_candidates.tsv` — 30 curated, `status=VALIDATED` known-ADC-asset rows (14 approved, 16 clinical-stage).
- `DATA/reference/adcdb_asset_antigen_crossref.tsv` (new, checked in) — each asset's antigen manually cross-referenced against `$ADCDB_PUBLISHED_PATH/ADCs/*.md`'s own `antigen:` wikilink field (source-verified per asset, not inferred from drug-name conventions), with an explicit `resolution_status` per row: 27 `RESOLVED_DIRECT` (a dedicated `ADCs/<asset>.md` file's own `antigen:` field), 2 `RESOLVED_BACKLINK` (`sigvotatug vedotin`, `bulumtatug fuvedotin` — no dedicated ADC file, resolved via the antigen file's own "Related ADCs" backlink instead), and 1 `UNRESOLVED_SOURCE_GAP` (`glembatumumab vedotin` — its ADC detail file is linked from `ADC.index.md` but missing from the local vault; no target was assigned rather than guessing one from memory). `scripts/build_target_seed_universe.py` (round 2 of PR #72) hard-fails if this file's `asset_entity_id` set drifts out of sync with `adc_candidates.tsv`'s `status=VALIDATED` set, or if a `RESOLVED_*` row's antigen file goes missing — a partial/stale seed universe must not be emitted silently.
- `$ADCDB_PUBLISHED_PATH/Antigens/<name>.md` — each antigen's own General Information table (`Gene Name`, `HGNC ID`, `Antigen ID`).
- `DATA/reference/uniprot_accession_map.tsv` (new, checked in) — UniProt accession per gene symbol, retrieved from the UniProt REST API and cross-checked against each antigen file's own `Uniprot Entry` mnemonic (all 23 matched exactly).

Result: **23 unique targets**, all `derisking_tier=A_CLINICAL` / `repurposing_status=ACTIVE` per the contract's own admission-gate definition (a real ADC construct against each has entered a human trial or is approved, per `adc_candidates.tsv`). `human_adc_exposure_evidence` is a deliberately separate, narrower claim: only `YES` when an *approved* asset exists for that target (approval implies documented dosing); a target with only clinical-stage (Phase 1–3) assets gets `UNKNOWN` there even though its `derisking_tier` is still `A_CLINICAL` — a registered trial is not the same evidence as documented human exposure, and `adc_candidates.tsv` has no per-asset dosing-evidence field to draw on for the clinical-stage-only case. `adcdb_cancer_types_with_precedent` is a distilled, deduplicated list of each target's documented trial/label indications (colorectal/colon/rectal-relevant terms are surfaced first, capped at the same total limit as everything else, and a term with explicit negative/exclusion context, e.g. "Excluding ... Colorectal Cancer", is never counted as precedent — see `scripts/test_build_target_seed_universe.py`). **Five targets have real, source-recorded CRC/mCRC precedent**: `CEACAM5` (Labetuzumab govitecan), `ERBB2`/HER2 (Trastuzumab emtansine/deruxtecan, Disitamab vedotin), `F3`/Tissue Factor (Tisotumab vedotin), `NECTIN4` (Enfortumab vedotin), `TACSTD2`/Trop-2 (Sacituzumab govitecan, Datopotamab deruxtecan) — none of this is a CRC efficacy or safety claim, only documented trial/label indication text; whether any of these five actually clears Modules B–F for a specific `indication_id` is unknown and untested.

**Scope boundary, stated explicitly, not hidden**: this v1 build only covers targets behind an already-clinical-or-approved ADC construct (`adc_candidates.tsv`'s curated 30-asset registry). ADCdb's broader local snapshot (`ADCDB_PUBLISHED_PATH/Antigens/`) lists ~300 additional antigens that would need per-target preclinical-evidence review to classify as `B_PRECLINICAL_ADC` vs `C_ANTIBODY_OR_BIOLOGY_ONLY` — that classification pass has not been started and is not part of this build.

**PR #72 round 1** (web-ChatGPT, `REQUEST_CHANGES`) caught that the first build was not actually fail-closed for a canonical generated artifact: the generator hardcoded the two env var names instead of reading them from `config/external_sources.yaml`, silently warned-and-skipped instead of hard-failing on a missing/extra crossref row or a vanished antigen file, unconditionally set `human_adc_exposure_evidence=YES` (upgrading "clinical stage" into "documented human exposure"), and the `adcdb_cancer_types_with_precedent` distillation had three live bugs — a negative-context indication string ("... Excluding ... Colorectal Cancer") counted as positive CRC precedent, `split(";")` shredding a cytogenetic-notation label (`t(9;22)(q34.1;q11.2)`) into a garbage fragment, and the CRC-priority cap not actually bounding total shown terms. All four fixed in round 2: the generator now reads `path_env_var` names from the YAML, reconciles the crossref file's `asset_entity_id` set against `adc_candidates.tsv`'s `status=VALIDATED` set and hard-fails on any drift (see `DATA/reference/adcdb_asset_antigen_crossref.tsv`'s new `resolution_status` column above), `human_adc_exposure_evidence` is `YES` only for targets with an approved asset, and the distillation logic excludes negative-context terms, splits on `;` only outside parentheses, and enforces `cap` as a true total — covered by new `scripts/test_build_target_seed_universe.py` regression tests. Output content is unchanged (still 23 targets) except for the corrected `human_adc_exposure_evidence` values and cleaner `adcdb_cancer_types_with_precedent` text.

Validated by `python3 scripts/validate_target_seed.py` against `schemas/target_seed.tsv` (header match, `target_id`/`target_symbol` uniqueness, `tgt_<symbol>` naming convention, controlled vocabulary, and the tier→status default-rule check) and `python3 scripts/test_build_target_seed_universe.py` (distillation regression tests).
